# ClearSign 0.5.3 — experimental native renewal
BariStore MIT source pinned at 56165783f31d3e441ae9f76df42c3cc55e239777; the build selects its developer portal, session, RemotePairing and misagent modules. No GPL Madeira code copied. Native Rust static library linked only in the host. No code is downloaded at runtime. No password login, no certificate creation/revocation, no application ID creation, no binary reinstall. Both profiles must match the installed signed identifiers, team, entitlements, device and all old certificate DER values; all candidates validated before either is installed. Device service acknowledgment for both profiles required before recording a receipt. A receipt is not an independent OS validation of actual runtime expiry. If a profile install fails partway, do not declare renewal successful.
 
One-time local setup: export a folder from the existing BariStore installation containing account.plist, pairing.plist, anisette-server and the matching anisette-*.plist files; optionally host-uuid and device-port. These files are authentication material. Do NOT upload or send them in chat, GitHub, or cloud storage. Select the local folder in ClearWidget. The import flow is not yet tested on Open Minis; BariStore may require an explicit local export. ClearWidget deliberately does not import signing-key.der or passwords. Delete the exported temporary copy after successful import. Session material is kept in device-only Keychain accessible after first unlock and staged temporarily under protected, backup-excluded local storage for the pinned library; no secrets logged. A hard termination could leave the protected temporary folder until next run. Keep LocalDevVPN running. Test manual renewal first, then enable automatic and alerts. No claim of unattended reliability before a locked-device test across the original expiry. Automatic request starts five days before expiry with at least six hours between attempts; iOS may defer or deny BGProcessingTask. For a revoked certificate or expired session, use external BariStore. If ClearWidget itself expires it cannot reliably launch to recover; Open Minis/BariStore is the recovery path, and automatic external recovery is not implemented. Never auto-revoke or retry sign-in. 
 
## On-device acceptance
1. Both embedded profiles parsed from the signed install, actual renamed bundle IDs recognized.
2. Import local folder, turn on LocalDevVPN, manual attempt; verify new expiry in external installer/device and both widget + app continue past old expiry.
3. Lock device, leave automatic enabled, test task and notification, then run across old expiry.
4. Test refusal: VPN off, expired session, changed certificate, mismatch profile; no secret logging, no new IDs, no destructive actions.
5. Test recovery after expiry externally. Do not remove stable 0.5.2.
