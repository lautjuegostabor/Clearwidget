# ClearSign v0.5.7 / build 13 candidate
Scope limited to signing and renewal. No Widget/ source, appearance, AppIntent metadata or latency changes.
- Foreground bootstrap accepts original unsigned IPA of same version, exactly app and widget, bounded ZIP. It uses existing independently authenticated account; single team required and must differ from original. No deletion or overwrite of existing copy.
- Explicit device-owner confirmation before certificate/device/App ID mutations. Native signer reuse; no certificate revocation, no silent replacement of missing private key. RSA key kept in separate local Keychain item before first portal call. Never included in exported session. New copy imports encrypted existing session via AES-GCM, no password/2FA repeat unless Apple invalidates session.
- On-demand and preventive renewal remain profile-only. Fix initial scheduling deadlock; request background renewal from five days before expiry, no promise of iOS background execution. Existing two-profile readback still required before claiming success. Requeue before network I/O, native cancellation on BG expiration, and signing-leaf fingerprint/expiration stamped in signed Info.plist for the new installation. The session transfer uses an updated encrypted export after bootstrap.
- New installation checked via installation_proxy and profiles independently via misagent. Profile chain trust is enforced by device installation, not an independent cryptographic attestation. No proof of actual post-expiry app launch.
- No on-device or compiler test performed in this development commit. Native CI is prepared with bootstrap unit tests for exact identifiers and rejected input. Need actual Apple account/device testing; multi-team selection not implemented; expired app cannot start its own recovery process. Existing encrypted external recovery remains profile-only.
