# Build 22 — Explicit authentication controls
Removed the arbitrary one-hour local authentication cooldown; no timestamp is consulted. User consent remains mandatory, no concurrent or automatic login, no automatic 2FA retry or change to Apple protocol or Anisette route. UI retains email and form, clears password only after native start accepted; displays status and progress, allows local session-save retry without another Apple login. Native state publication synchronizes BUSY release and prevents double code submission. Regression tests cover immediate explicit retry after internal launch failure, consent, input bounds, 32 authentication states plus 32 signing states. Existing renewal timing (six-hour automatic profile renewal retry) is unchanged; it is separate from Apple login. On-device authentication still unverified. No edits to widget, weather, native authentication protocol, or renewal engine.
